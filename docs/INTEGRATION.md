# Verified consumer configurations

The library's browser runtime and its development toolchain have separate
requirements. Use Node 24+, React 19.3.1 and a browser satisfying
[the production boundary](../PRODUCTION.md).

| Consumer                                       | Development toolchain | Assets and startup                                                                 |
| ---------------------------------------------- | --------------------- | ---------------------------------------------------------------------------------- |
| [First interface](../examples/first-interface) | Vite 7.3.7            | Packaged layout WASM and default font; no font generation                          |
| Generated Canvas2D / Three.js projects         | Vite 8.3.5            | Packaged layout WASM; licensed source font generated by `predev` / `prebuild`      |
| [Kestrel Survey](../examples/kestrel-survey)   | Vite 8.3.5            | Packaged layout WASM and two committed font atlases; font regeneration is optional |

These configurations select exact tool versions. They do not imply that every
Vite version, plugin combination or browser environment has been tested.

## Browser examples

[Open the minimal counter in StackBlitz](https://stackblitz.com/fork/github/VictorQueiroz/ludic-canvas/tree/main/examples/first-interface?file=src/main.tsx).
The `/fork/github/` URL creates a fresh editable copy. An existing imported
project can retain an older configuration after the source branch changes.

The example pins Vite 7 because the Vite 8 Rolldown WASI binding failed inside
WebContainers during qualification. The same failure is tracked
[upstream](https://github.com/stackblitz/starters/issues/118). That is a
development-server failure before Ludic Canvas starts; rebuilding Yoga or fonts
does not repair it.

For Vite 7, use the example's [configuration](../examples/first-interface/vite.config.mjs).
It excludes the ESM library from dependency prebundling so the layout and default
font URLs remain relative to the installed files. React, both JSX runtimes and
the reconciler's CommonJS entry points remain prebundled. This prevents an HTML
fallback response from being passed to `WebAssembly.instantiate()` and avoids
missing JSX exports. Keep one React instance per application.

## Automated consumer contract

```sh
npm run test:consumer -- --project=chromium
LUDIC_CONSUMER_PACKAGE=registry npm run test:consumer -- --project=chromium
```

The default suite packs the current library. Registry mode uses the exact npm
version selected by the first-interface manifest. Both modes copy projects out
of the repository, install normal dependencies, and execute the packaged CLI for
both generated starters. No workspace alias supplies the library.

Every project runs its actual `npm run dev` lifecycle, then its production build
and preview. The browser must acquire layout WASM with its binary magic bytes and
font PNG bytes, initialize the renderer and perform pointer/keyboard or pause/modal
interaction. A successful HTTP response containing HTML is a failure. Vite's
JavaScript URL-export modules are distinguished from the fetched image bytes.
Reports retain artifact integrity, checkout identity, runtime asset responses,
browser errors and server logs.

CI runs packed consumers on Chromium, Firefox and native macOS WebKit, plus the
committed registry consumers on Chromium. These are correctness checks. Software
GPU CI, Playwright WebKit and viewport emulation do not certify physical phones,
screen readers or hardware performance. See the
[qualification record](QUALIFICATION_RESULTS.md) for acquired device evidence.

Linux browser consumers run headed under Xvfb with the same software-Mesa setup
as the existing browser contracts. The first headless Linux Firefox candidate
could not acquire WebGL 1. That failure was in the CI graphics environment;
startup deadlines and SDK behavior were not changed to accommodate it.

## 0.7.0 consumer update

Both standalone examples pin the published 0.7.0 artifact. The minimal counter
keeps the Vite 7 toolchain, updated to Vite 7.3.7 and esbuild 0.28.2 to resolve
the advisories reported for its previous development dependencies. Its npm audit
reported zero advisories after the update; this is a dependency snapshot, not a
security certification. The original hosted acquisition used 0.6.0/Vite 7.3.5;
current hosted and consumer outcomes are recorded in
[the release verification record](RELEASE_0_7_0.md).
