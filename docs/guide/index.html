Generate a game project

Node 24+ and npm are enough. The initializer creates a new Vite + TypeScript project with a world canvas, a transparent Ludic Canvas HUD, controlled buttons and a slider, a licensed font and a configured font pipeline.

Choose --template three for a Three.js world. Both templates use one application-owned loop and separate world/UI canvases. The default directory is ludic-game; the default template is canvas2d. Existing non-empty directories and symlink destinations are rejected. The initializer generates files; you choose when to install dependencies.

Pause, resume and reset it, and change simulation speed using pointer or keyboard. npm run build generates fonts, checks TypeScript and creates dist/. Your first interface

Start with Node 24+, npm, and a browser with WebGL and WebAssembly enabled. The package includes its layout module and a default font; your first interface needs no font generation or native toolchain.

Open the minimal counter in StackBlitz ↗ Edit one component and try pointer or keyboard input. The standalone project pins a WebContainer-compatible Vite version and preserves the package's WASM/font URLs.

1. Create a project

Use Vite's React + TypeScript template, then install Ludic Canvas and its supported React version. Keep React DOM on the same version as React in the template.

Already have a Vite project with automatic React JSX compilation? Install the package and React 19.3.1, then adapt the canvas setup below to your scene. The react-ts template already includes JSX and TypeScript configuration.

Replace all of src/main.tsx with this complete example. Keep the template's index.html and vite.config.ts. The code creates a sized canvas and mounts the custom renderer with ui.render().

What you should see

Open the local address printed by Vite. A dark screen shows “Your first game UI”, a score of 0, and a “Collect a coin” button. Click it or use Tab and Enter: the score should increase. If the canvas stays blank, start with troubleshooting.

Check the production bundle with npm run build. The starter source is included in the repository and built against an installed package during CI. Custom fonts, game-loop control and shared rendering can come after this first screen.

createUI() starts drawing automatically. Leave destroy() for scene teardown; calling it immediately after render() removes the interface. Each canvas needs a nonzero CSS size and a positioned parent for its accessibility mirror.

Architecture

React→Retained nodes→Yoga WASM→WebGL

The React reconciler owns a retained host tree. Each host node owns a Yoga layout node. After layout, boxes are read in one batch from WebAssembly memory. The painter traverses the tree, animates visual values and sends primitive quads to a WebGL batch. Pointer input hit-tests the most recently painted frame. A separate DOM mirror provides keyboard controls.

The package owns UI infrastructure. Applications own domain models, state, persistence, audio, scene effects and asset catalogs. Feed immutable view data into components and pass actions back to the simulation. The library has no game-state schema or ECS dependency.

The native layout ABI is versioned and checked at load. The custom React host config is kept internal and paired with an exact supported React version because react-reconciler has an unstable API.

Experimental native hosts

The experimental portable core separates React composition and interaction from layout, drawing and host services. The same component tree can run through the browser adapter or the repository's standalone macOS proof with Hermes, native Yoga and Skia/Metal.

ludic-canvas/core exports the rendering/layout/host contracts, a command recorder and a headless host. Browser applications retain direct WebGL drawing and DOM text editing. Native builds compile the JavaScript bundle to Hermes bytecode; they do not translate React into platform widget source.

The first native host is an experimental macOS development bundle. Android, iOS, Windows and Linux ports, distribution packaging, native editing parity and device/accessibility qualification remain future work. Read the portability architecture and build instructions for exact boundaries.

Compose primitives

View lays out and paints panels, gradients, borders, glows and fill meters. Text measures and draws MSDF glyphs. Image loads raster images or rasterizes SVGs with cover/contain/fill fitting. Line draws solid or marching dashed connections.

Use ordinary React components and hooks to compose buttons, panels and screens. Host refs expose internal nodes and are not part of the supported public API. Plain strings belong inside Text. Images are referenced through their src property.

Layout & styling

Layout follows Yoga flexbox, rather than browser CSS. Dimensions accept numbers in CSS pixels, percentage strings and 'auto'. Supported properties include flex direction, alignment, wrapping, grow/shrink, absolute positioning, min/max size, margin, padding and gap. The default direction is a column. See LayoutStyle for the complete supported surface.

Colors currently accept hexadecimal strings (#rgb, #rrggbb, #rrggbbaa) and rgb()/rgba(). Named colors and CSS variables are not supported. Text style is set on each Text node and does not inherit from View. There is no browser cascade.

Use overflow: 'hidden' for rectangular scissor clipping and overflow: 'scroll' for vertical wheel/touch scrolling. Border radius rounds a node's own background and images; child clipping remains rectangular. Scale and translation propagate through descendants; visual transforms do not reflow Yoga layout. Clips remain axis-aligned. zIndex controls sibling paint order.

onLayout is queued after layout and reports the local box in CSS pixels. Avoid feedback loops that continuously resize the same node. transition and enter durations are milliseconds; line animation speed uses pixels per second.

Images & fonts

Omit assets to use image URLs directly. Alternatively pass a resolver function that maps an identifier to image metadata. Unknown catalog identifiers render no image; explicit preloading rejects unknown identifiers. Failed requests call onError and cause preloads to reject. Clear failed or changed entries with invalidateImages(ids) before retrying or loading replacement content. Fetches and decoded uploads are root-owned and disposed when it is destroyed.

Kerning and explicit font fallback

Register one to four MSDF/MTSDF faces. The first is the default. Set fontFamily to a registered name or an ordered array of one to four unique registered names. Each codepoint uses the first face containing it; system fonts are never consulted. Every atlas must include space and question mark. A codepoint absent from the complete chain renders as ? from its primary face.

Measurement, wrapping, alignment, ellipsis and drawing use the same selected glyph and face. Fallback faces share a baseline, and their metrics may enlarge a line. Atlas pair adjustments apply between adjacent glyphs from the same face, including across emphasis markers; line and face boundaries reset pair context. Set fontKerning: 'none' for unkerned spacing. Trailing spaces are excluded from line width.

The optional atlas kerning array uses { unicode1, unicode2, advance } records. Advance is an additive pair adjustment in the same metrics.emSize units as glyph advances. Existing JSON without pairs stays supported. The CLI extracts legacy FreeType kern pairs; a GPOS-only font can export zero pairs. Rebuild old generated atlases to acquire available pairs.

onFontDiagnostic is opt-in and runs in a microtask after synchronous layout. It reports the missing codepoint, ordered font names, replacement and a suggested charset/fallback fix; it does not include the original string. Reports are deduplicated per codepoint/ordered chain and capped at 1024 per root lifetime. Throwing callbacks go to onError. Add missing characters to the CLI charset/characters configuration and regenerate.

The bundled face covers Latin-1 and selected punctuation. Kerning and per-codepoint fallback do not implement bidi, grapheme-aware wrapping, GPOS positioning, complex-script/ligature shaping, editable text or automatic emoji fallback. Use native DOM text/editing for those requirements.

Generate custom atlases with the packaged font CLI. It uses the bundled WASI compiler and works without CMake, FreeType installation, native executables or network access. Font licenses remain with their fonts. Native tools are needed only to rebuild the compiler itself.

The texture budget is a soft LRU budget. Recently visible textures remain resident even if they exceed it. SVGs are quantized and rasterized at the requested pixel size. Cross-origin image and font URLs require CORS headers.

Font atlas CLI

The installed package exposes ludic-canvas fonts. Node 24+ runs a bundled, offline WebAssembly compiler containing FreeType, Brotli and msdf-atlas-gen. TTF, OpenType CFF/OTF, WOFF and WOFF2 outline fonts are supported; collections and bitmap-only fonts are outside this release.

1. Create a configuration

Edit ludic-canvas.fonts.json and set your font paths. Every path is relative to this configuration file.

2. Generate and register

This creates interface.png, interface.json and font-atlas-manifest.json. The manifest stores content hashes for caching and uses relative output names. The font name font-atlas-manifest is reserved, including case variants, to prevent a filename collision. Register the generated files through the existing fonts option:

For deployments under a URL prefix, include your application's base path in those URLs. The source TTF/OTF/WOFF files are not needed by the browser.

3. Integrate with development and builds

Unchanged sources, configuration and compiler bytes reuse cached output. Modified or damaged PNG/JSON files are regenerated. --force always regenerates. A failure in any face leaves existing output files unchanged; successful generations replace the configured files but do not delete old fonts removed from configuration.

Configuration reference

size is atlas pixels per em (8–128, default 48), independent of runtime fontSize. distanceRange is the distance range in atlas pixels (1–32, default 6). charset uses msdf-atlas-gen expressions, such as [0x20, 0x7E], [0xA0, 0xFF]. A font-level charset overrides the configuration default. characters adds literal Unicode characters. Space and ? are always included. Missing requested characters fail with their Unicode codepoints; runtime text outside the generated set uses the fallback.

Variable fonts accept four-character axis tags: "variations": { "wght": 600 }. Unknown axes and values outside the font's axis range fail. Each face name must contain 1–64 ASCII letters, digits, hyphens or underscores and be unique ignoring case. The compiler supports at most 16,384 requested codepoints and an 8192×8192 atlas; choose the character coverage your interface needs.

The JSON schema is also exported as ludic-canvas/font-atlas.schema.json for editors. --help and --version need no compilation. Node currently emits its standard WASI experimental-feature warning during generation; a successful command still exits with status 0.

Game-loop integration

Place the game world and UI in the same positioned parent. The game owns the world canvas; Ludic Canvas draws a transparent overlay.

The loop below assumes your application provides game and Hud. Adapt it to your engine, or explore the complete courier example.

A transparent overlay canvas is the simplest integration with any browser rendering engine: give the world and UI separate canvases in the same positioned container. For shared rendering, pass a WebGL 1 context and call frame() after the game pass. Canvas dimensions remain engine-owned by default when a context is supplied.

The UI binds the default framebuffer and changes viewport, buffers, shaders, texture bindings, vertex attributes, blending and depth/cull/scissor state. It does not snapshot or restore the engine's GL state. Reset or invalidate your engine's state cache before its next draw. Shared WebGL 2 contexts and rendering to an engine framebuffer are not supported. An overlay canvas is the supported route for engines using WebGL 2, WebGPU or other renderers.

New React renders commit asynchronously. Re-render after game state changes; do not re-render solely to advance animations. Call stop() to pause automatic frames and destroy() when leaving a scene. Destroying is idempotent and allows the same canvas to be mounted again.

Native text entry

TextInput and TextArea combine a Yoga box and WebGL decoration with a persistent native DOM editor. The browser draws field text, placeholder, caret and selection while focused and unfocused. Its editing, direction and fonts are independent of the canvas atlas renderer.

Update the string synchronously from onValueChange; debounce persistence or expensive derived work separately. Unaccepted edits revert to the controlled value. Native input callbacks flush their React updates before reconciling the value; prop echoes do not rewrite the DOM value, preserving selection and native undo. During IME composition, drafts are reported without replacing the editor value. An external value differing from the live draft is deferred until composition ends and takes precedence over later drafts. Do not transform composing text. onSubmit requests single-line Enter submission outside composition; Enter inserts a newline in TextArea.

Fields share this root's Tab order, controller focus, modal trapping/restoration and focus-driven scroll reveal. Editing keys stay with the browser; Tab and non-composing Escape participate in UI focus/dialog behavior. Global game capture listeners must respect UI focus. Native fields have one labelled accessible element; error attaches an error description and aria-invalid. Static canvas text retains its existing accessibility limits.

Use a nonzero Yoga box. Defaults are 100% width and heights of 44/120 pixels. style lays out/decorates the field; textStyle.padding controls native content inset (default 10 pixels). Yoga padding does not place editor text. Native font size, tracking and line height follow root text scaling. Supply CSS/FontFace fonts through your application; registering an atlas does not register a native font. Native script rendering does not add shaping or bidi to canvas Text.

A ref exposes focus(), blur() and select() after the first painted frame. Focus/select return false when unavailable or outside the active modal. ui.focus(id) also supports fields. Unmount and root destruction remove editors, descriptions, callbacks and handles. Context loss or zero-sized canvas suspension disables and hides them until painting resumes.

Layering boundary: use fields in topmost form panels or dialogs. DOM field text is above the canvas; arbitrary interleaving with canvas siblings, rotation/skew, canvas-only screenshots and rich-text editing are unsupported. Fields follow inherited translation, uniform scale, opacity and rectangular scroll clips; background fields hide while another modal owns input. Keep the canvas and its overlay container aligned; custom accessibilityContainer integrations must provide the same origin and dimensions. Continue calling the application-owned frame loop during viewport/keyboard changes.

The catalogue's Edit profile dialog demonstrates both fields in two independent roots. See the editing contract and qualification record. Synthetic composition and mobile emulation do not establish real IME, phone-keyboard or screen-reader qualification.

Input & accessibility

Use onPress, onHover, hoverStyle, pressStyle, disabled and hotkey on primitives. Give every pressable a meaningful label; descendant text supplies a fallback. Pointer input, vertical wheel scrolling and touch drags are supported. Canvas hotkeys activate only while that canvas or one of its mirrored controls has focus, so roots do not steal each other's keys.

Each painted pressable is mirrored by an invisible DOM button in paint order. Tab moves between buttons and Enter/Space activates them; focus is drawn in the canvas. Canvas focus itself enables scoped hotkeys. Set announce on Text to publish its changed content to a polite live region.

This is a limited control mirror, not complete accessibility semantics. It does not expose all static canvas text as a document. Native text fields are described in Native text entry. Modal focus scopes and controller action methods are described in Controls, modals & controllers. Validate the complete interface with keyboard users and assistive technology. Provide a separate DOM interface where richer semantics are needed.

Reduced motion initially follows the browser preference; setReducedMotion(true) disables enter transitions, tweens, hover interpolation, glow pulses, breathing and marching-line motion. setTextScale() changes both text measurement and drawing. Dynamic system preference changes require the application to call the setter.

Controls, modals & controllers

The shared controlled components provide common interaction mechanics without a visual theme. Use Dialog for pause menus, confirmations and inventory inspectors. The topmost dialog restricts this root's hotkeys, Tab order and spatial navigation, focuses its first control, and restores each scope's trigger when it closes. Your game separately controls simulation and its own global input bindings.

Slider handles pointer capture/cancellation, step snapping, range clamping and keyboard adjustment. The application owns its value and draws the track/thumb through a render function. For custom drag controls, pointer events bubble in CSS pixels; local coordinates use the node's unscaled layout space. Clear drag state on onPointerCancel. preventDefault() disables built-in press/touch scrolling; stopPropagation() stops ancestor callbacks.

For text entry, use controlled TextInput/TextArea inside a topmost panel or Dialog, or open an application-owned native DOM dialog. Keep the value in the game's React/store state. See the native editing contract. This gives the browser responsibility for selection, copy/paste, mobile keyboards, IME and assistive technology. The library's mirror exposes interactive controls and announcements; static canvas text is not a complete accessible document. Provide a DOM alternative when the complete experience needs document semantics.

Wheel & world input

Use onWheel when a map, viewport or custom control already receives pointer input through a View. Wheel input selects the frontmost input surface and bubbles through its ancestors. Overlapping controls, disabled controls and block panels keep events away from unrelated surfaces behind them, even without a wheel handler.

UIWheelEvent exposes canvas CSS-pixel coordinates x/y, element-local localX/localY, raw deltaX/Y/Z, deltaMode (0 pixels, 1 lines, 2 pages), modifier keys and defaultPrevented. It is not a scroll-position notification. Choose camera sensitivity and trackpad-pinch policy in the application. Existing vertical scrolling uses 32 pixels per line and the scroller height per page.

Handlers run before default scrolling. preventDefault() cancels the library default and requests browser cancellation. stopPropagation() stops ancestor callbacks and DOM propagation but leaves default scrolling intact; it does not suppress other listeners on the same DOM element. Native textareas scroll themselves before chaining to an ancestor ScrollArea at their boundary. Disabled children still allow ancestor scrolling. Custom handlers also work on TextInput/TextArea.

For a camera controlled outside the UI tree, query the owning root directly:

isPointerOverUI({ clientX, clientY }) accepts viewport coordinates, including a browser pointer/wheel event. It reads the latest painted geometry without requiring a pointermove, dispatching events or drawing. Controls, wheel surfaces, scroll regions and block boxes count, including disabled controls. Ordinary decorative/layout boxes do not; use block for panel backgrounds. Clipping, transforms, stacking and pointerEvents apply. A modal reserves the root's entire canvas. Points outside the canvas, an unpainted/suspended root and destroyed roots return false.

A full-size map interaction View is itself UI, so use its onWheel instead of expecting the external guard to exclude it. The query reports geometry, not pointer capture ownership: retain the existing owner of an in-progress drag. Keep calling frame() after layout or viewport changes. Abort application listeners on scene teardown.

Try the map-and-sidebar example with both arrangements or read its source.

Large collections & performance

Use ordinary components for small HUDs and short menus. Use VirtualList for a large, fixed-height, single-select collection: it mounts the viewport and overscan while your application owns the full dataset and selection.

Keep item keys stable and update arrays immutably. Rows may unmount, so store persistent item state outside them. The initial key/index metadata remains linear in item count; mounted React/Yoga nodes scale with the visible window and overscan. Fixed row height is explicit: supply a larger height when text scale or localization needs more space.

Arrow keys, Home/End, PageUp/PageDown, prefix search and ui.navigate() use logical items and skip disabled choices. Focus and selection are separate. Options expose logical position/size and one Tab stop. Active, pending-focus and pointer targets can retain three extra rows.

Focus requests resolve false on missing/disabled targets, modal rejection, supersession, removal or teardown. The last active row remains available for modal focus return. Reordering uses stable keys, and a surviving viewport anchor follows data and explicit height changes.

Listbox options contain visual content. Put independent buttons, checkboxes and editors outside options; interactive grids and variable-height rows require a different collection contract. The lower-level createScrollHandle provides viewport/offset observation for custom compositions.

Try Kestrel Survey → Collection → Regional archive: 4,000 records, custom row layouts, two font families and responsive sizing, inside the existing 3D game loop. The three live mission samples remain a short ordinary list.

The performance lab compares matched 400/4,000-item collections and a 40,000-item windowed probe. Read the full collection contract and measurement limits. Browser tests do not replace physical-device and screen-reader qualification.

Production support & limits

Ludic Canvas is an interface layer for desktop and mobile browser games. Build HUDs, menus, inventory grids, dialogue panels, maps and settings by composing primitives. A general-purpose renderer does not automatically supply every widget, text system or engine adapter.

Choose the right boundary

Use caseSupport and integration

Sliders, toggles, tabs and drag interactionsUse the unstyled controlled components in the catalogue, or compose custom pointer/key behavior from primitives. The game owns values, selection, inventory rules and persistence.

Editable canvas text, bidi, GPOS positioning, ligature shaping, complex-script shaping and automatic emoji fallback are not implemented.

Ordinary ScrollArea children remain retained; variable-height lists and interactive grids need a separate contract. The retained tree is traversed each frame. Rotation, skew, stencil masks, rounded child clipping, arbitrary shaders and 3D world-space UI are outside the current renderer.

Recovery and ownership

The layout reactor uses ABI 2; custom layout URLs/bytes must match this package version. Prefer the bundled default, or update your deployed reactor when upgrading. Every root owns its Yoga instance, fonts, textures, input listeners, focus scope, caches and animation state. Destroy roots when scenes leave; use an AbortSignal for asynchronous setup and teardown. Two roots can coexist without a game singleton. A canvas accepts one root at a time, including across bundled copies.

Context loss suspends rendering and controls. Restoration rebuilds font textures and the GPU batch, preserves the React tree, and reloads visible image assets. Fonts retain their source blobs for recovery. If recovery fails, onError runs and the root remains suspended; the application can destroy and recreate it. A zero-sized canvas also suspends controls. Call frame() regularly when using a game-owned loop.

Resource and text limits

Defaults: 32 MiB per downloaded resource, 8192 pixels per uploaded image dimension (also capped by the GPU), four concurrent image tasks, 64 MiB combined font textures, and a soft 64 MiB image cache. Set resourceLimits and textureBudgetBytes for your target devices. Decoding can temporarily use additional browser memory; downloaded-byte limits do not bound decoder memory. Visible or explicitly preloaded images can exceed the soft cache budget. FrameInfo.textureBytes measures resident image textures, excluding fonts and browser overhead.

Failed images remain failed until invalidateImages(ids) clears them. Call it after replacing content or before retrying a failed request. Fetches use browser CORS rules. Texture uploads preserve bindings and pixel-store settings; a UI drawing pass intentionally changes other GL state. Draw UI last and reset engine state before the next pass.

Text uses build-time MSDF/MTSDF atlases and runtime glyph placement. Include all localized glyphs in the CLI configuration. Explicit ordered fontFamily chains select registered faces. Atlas pair kerning uses the selected face. Unknown glyphs use ? and can trigger opt-in onFontDiagnostic reports. Long words break at codepoint boundaries; CRLF is normalized. Use maxLines with textOverflow: 'ellipsis' for labels, and overflow: 'hidden' for clipping. This is not a Unicode shaping engine. The text cache retains at most 2,000 layouts and 100,000 glyph quads; very large strings are not cached.

The font CLI reads each source with a 128 MiB cap, compiles one face at a time in a worker with a 120-second deadline, and locks the output directory against concurrent writers. A compiler failure preserves existing generated files. Output files are renamed individually; a power failure or filesystem error during publication can still interrupt a set. Generate into a build directory and deploy the complete build atomically. After a killed process, remove the named stale lock only after confirming no generator remains running.

Release qualification

CI runs Node tests and packed-package consumers on Linux, macOS and Windows, plus browser contracts on Chromium, Firefox and WebKit, with Android-sized Chromium and iPhone-sized WebKit emulation. Browser tests cover pixel alpha/orientation, inherited transforms, scrolling, modal keys/focus, custom pointer controls, context recovery, cleanup and a 1,000-node batch case. The draw-call check is a batching regression. Use the performance lab to acquire raw CPU frame-call, commit-latency and RAF-interval samples with explicit device/workload budgets. The lab does not measure GPU execution or memory.

For each game release, test representative scenes on physical target phones and desktops, including low-memory devices, browser zoom, orientation changes, screen readers, text scaling, background/resume and your engine's GL state reset. Mobile emulation does not certify Safari on an iPhone or Chrome on an Android device. Measure frame time and memory with your assets and scene complexity before setting a performance budget.

Changesets opens a version PR after changes merge to the default branch. npm publication occurs after that version PR merges and all checks pass, using trusted publishing and provenance. The API is still versioned below 1.0; pin compatible versions and review release notes.

Troubleshooting

Check the browser console and the Network panel first. The symptom usually points to a small setup issue.

SymptomWhat to check
Blank canvasGive the canvas and parent a nonzero CSS width and height. Await createUI(), call ui.render(), and leave the root mounted. With autoStart: false, call ui.frame(now) in your loop.
UI disappears immediatelyCall ui.destroy() only when the scene unmounts. It releases the React tree, listeners, layout and GPU resources.
JSX errors or an invalid hook callUse a .tsx file with automatic React JSX compilation. Match React to 19.3.1 and check npm ls react for duplicate copies. Mount this component tree through ui.render().
Missing WASM, atlas or imageLook for failed requests. Serve the application through your bundler rather than opening an HTML file directly. Check the deployment base path; cross-origin URLs need CORS headers.
Text shows question marksThe active atlas lacks those glyphs. Add the characters or Unicode ranges to the font configuration, regenerate, and select the registered fontFamily. See the font guide for coverage and shaping limits.
Styles do not inherit or match CSSSet text styles on each Text. Layout follows Yoga flexbox, with no CSS cascade or media queries. Use onLayout or a viewport observer to choose a responsive composition.
UI does not reflect game stateReact renders commit asynchronously. Re-render after state changes, or subscribe with a hook as in Orbital Relay. Calling frame() advances drawing; it does not fetch new game state.
WebGL is unavailableCheck that the browser/device permits WebGL, and pass failures through onError. Use a separate UI canvas alongside a WebGL 2 or WebGPU game; shared contexts currently require WebGL 1.

Still stuck? Open an issue with the package version, browser/OS, console error and a small reproduction. The API reference lists exact supported properties.

Build, verify & contribute

Node 24 or newer is required for repository tooling. The native build needs CMake 3.28+, LLVM with wasm32 and wasm-ld. The bootstrap downloads SHA-256-pinned WASI sysroot and compiler-rt inputs. Yoga sources are pinned by version and hash. The committed layout module lets consumers and Vercel build without the native toolchain.

The public repository uses a fresh history and contains the library, generic examples, font notices and reproducible build sources. The API reference is generated from emitted TypeScript declarations during every documentation build. Run npm run check before a release. The Vercel project builds npm run docs:build and serves site/ from the repository root.

Compatibility: React 19.3.1 is the tested peer version; react-reconciler 0.34.0 is pinned. Browser requirements include WebAssembly SIMD/bulk-memory, WebGL 1, createImageBitmap and Pointer Events. CI exercises Chromium, Firefox and WebKit with desktop and mobile-emulated viewports. Physical device certification remains application-owned; see Production support & limits.
