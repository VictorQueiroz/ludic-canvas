INSIDE THE EXAMPLE / 2D

How Orbital Relay uses Ludic Canvas.

The game owns the world.

The application draws the ship, cargo, beacons and debris with Canvas 2D. A transparent WebGL 1 canvas sits above it. Ludic Canvas owns the HUD, manifest, cargo tabs and pause menu.

State flows in. Actions flow out.

React reads immutable simulation snapshots at 10 Hz. Components call game actions to select a destination, boost or pause. Oxanium and Space Mono come from separate interface and mission modules; the UI root combines their generated MSDF atlases.

One application-owned loop.

The loop advances the simulation, draws the world and calls ui.frame(now). ResizeObserver keeps both canvases aligned. Modal scopes isolate pause input, and scene teardown destroys the UI root and removes observers and listeners.

INSIDE THE EXAMPLE / 3D

How Kestrel Survey uses Ludic Canvas.

Separate renderers, shared dimensions.

Three.js owns the WebGL 2 scene, rover, terrain, camera and shadows. Ludic Canvas draws the complete custom interface in a transparent WebGL 1 overlay. Both renderers receive the same CSS dimensions; they use separate graphics contexts.

Connect the world to the HUD.

Three.js projects site positions into CSS-pixel coordinates for canvas labels. Terrain clicks travel through the UI input surface to a Three.js raycast. Blocking panels keep their clicks out of world navigation. Camera sliders and modal menus use the library's pointer and keyboard semantics. Collection → Regional archive opens a 4,000-record VirtualList with logical focus, application-owned selection and responsive rows; the three live samples remain a short ordinary list.

Keep ownership explicit.

A plain game model owns navigation and sampling. React reads snapshots at approximately 14 Hz. Feature modules define two MSDF font families, composed at createUI. One loop advances bounded simulation steps, draws Three.js and frames the UI. Each renderer handles its context recovery and disposal.
